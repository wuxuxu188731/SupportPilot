# SupportPilot RAG 知识库：8 篇售后政策文档设计

## 1. 文档状态

- 日期：2026-08-07
- 状态：已获用户批准（方案 A）
- 用途：为智能工单助手的 RAG 知识库生成 8 篇 Markdown 政策文档，作为入库数据源

## 2. 背景与目标

SupportPilot 企业知识库 RAG MVP 需要一组 Markdown 政策文档用于入库、分块、
向量化与离线评测。文档按 Markdown 标题层级分块（citation 携带 heading_path），
目标每块 400～700 tokens。本设计定义文档的身份设定、共用事实基线、每篇文档的
大纲与写作规范，保证 8 篇文档共用数据严格一致。

- 公司身份：虚构品牌「云舟商城」，运营主体「云舟科技有限公司」，纯自营模式。
- 存放位置：`docs/knowledge/`，文件名带两位序号。
- 篇幅：每篇约 2000～3500 中文字。

## 3. 事实基线表（唯一数据源）

以下数据为 8 篇文档共用设定，任何文档取值不得偏离本表。金额单位人民币（¥），
「天」未注明时指自然日。

## 4. 8 篇文档大纲

文件名统一为两位序号 + 中文名，存放于 `docs/knowledge/`：

1. `01-售后服务总则.md` — 适用范围与渠道、服务时间、申请入口、必要凭证、
   通用处理流程、责任边界、不受理情形、与专项政策的关系（总入口）。
2. `02-退货与换货政策.md` — 无理由退货（分级时限）、质量问题退换、商品状态、
   包装、配件与赠品要求、运费承担、不可退换商品、换货缺货处理。
3. `03-退款政策.md` — 原路退款、到账时间、部分退款、退款失败、分期付款、
   礼品卡/余额/优惠券/积分返还、发票处理。
4. `04-物流配送与异常处理.md` — 发货时效、预计送达、物流状态定义、延迟判定、
   丢件/破损/错发/漏发/拒收/地址错误处理与所需材料。
5. `05-延迟赔偿与售后补偿.md` — 可赔情形、金额与上限、排除条款、不可抗力、
   重复补偿限制、VIP 额外补偿、人工审批。
6. `06-商品质量与保修政策.md` — 质量问题定义、人为损坏判定、分品类保修期、
   保修凭证、检测流程、维修与换新条件、费用承担、保修失效情形。
7. `07-订单取消与修改政策.md` — 未付款/已付款取消、发货后拦截、改地址、
   拆单、缺货、预售、价格保护、重复下单合并。
8. `08-VIP会员权益.md` — 等级与升降级、退货期延长、免运费、优先客服、
   专属补偿、生日权益、权益有效期、活动期与特殊商品限制。

## 5. 每篇文档的内部结构

统一采用以下结构，适配 Markdown 标题分块：

```text
# 《文档名》

> 文档信息：版本 v1.0 ｜ 生效日期 2026-07-01 ｜ 编制单位：云舟商城客户服务部

## 1. 章节
### 1.1 子节
编号条款或表格
```

- 标题层级不超过三级（# / ## / ###）。
- 每个章节自包含核心结论，具体数据优先用表格或编号条款呈现。
- 涉及其他政策的内容使用「详见《XX政策》」交叉引用，不重复展开。

## 6. 写作规范

1. 所有数字一律取自第 3 节事实基线表，禁止即兴改写。
2. 金额统一「¥」前缀或「元」；时限注明起算点（签收次日起算、自发放之日起等）。
3. 「工作日」与「自然日」必须明确区分：退款到账、人工处理为工作日；退货、
   保修、送达时限为自然日。
4. 语言正式、面向企业客服场景，不出现真实品牌或真实企业信息。
5. 每篇正文 2000～3500 中文字。

## 7. 实现步骤

1. 建立 `docs/knowledge/` 目录。
2. 按第 4 节顺序逐篇生成 8 篇文档，每篇完成后对照事实基线表自检：
   - 数值与基线表一致；
   - 交叉引用指向正确的文档名；
   - 起算点与工作日/自然日标注齐全。
3. 全量交叉检查：任意数据项在 8 篇中出现多次时取值一致（可用 grep 抽查）。
4. 交付清单：8 篇文档 + 本设计文档（作为事实基线表的落盘副本）。
