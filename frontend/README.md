# SupportPilot 前端（frontend/）

SupportPilot 电商售后客服工作台的 Web 前端。技术栈：**Vue 3 + TypeScript +
Vite + Vue Router + Pinia + Axios + Naive UI + Vitest**。

当前阶段已实现：

- 注册 / 登录 / 登录状态恢复 / 退出登录（认证闭环）；
- 企业列表 / 创建企业 / 企业选择与切换 / 当前角色展示（企业上下文闭环）；
- **客服对话闭环**：会话列表（新建/切换/加载更多）、服务端历史恢复、
  发送消息（独立长超时、不自动重试、输入法安全、防重复提交）、
  Agent 最终回答与结构化展示（知识引用、检索摘要、处理过程时间线、
  待审批提案卡片）、会话系统提示词设置、企业切换时聊天状态清理与
  旧企业迟到响应隔离；
- **审批中心闭环**（第四阶段）：审批列表（待审批/全部/已批准/修改后批准/
  已拒绝筛选、分页加载与去重、无总数不伪造）、审批详情（基本信息、
  请求版本、版本时间线、决定摘要、Run 完整状态）、admin 批准 /
  修改后批准 / 拒绝（不可逆确认对话框、200/201/202 状态码分流、
  409/422/403 处理）、Run 显式恢复（可重试条件派生、503 保留事实可重试）、
  聊天待审批卡片一键跳转审批详情、企业切换时审批状态清理与旧企业迟到
  响应隔离、列表 30s 低频刷新与 Run 短周期轮询（仅页面可见且非终态）。
- **知识库闭环**（第五阶段，本文件下文详述）：文档列表（本地搜索/
  筛选/排序）、文档详情（基本信息、版本历史、最近入库任务）、
  admin 上传新文档/新版本、停用/启用、入库任务查询与轮询、
  agent 只读视图。
- **成员管理闭环**（第六阶段，本文件下文详述）：成员列表（本地搜索与
  角色筛选）、admin 添加成员（按精确用户名）、修改成员角色、移除成员
  （后两者均需二次确认）、agent 只读视图、自己那一行不提供自我管理入口、
  企业切换时成员状态清理。

## 环境要求

- Node.js ≥ 20（开发环境使用 Node 24 验证）
- npm ≥ 10

## 安装依赖

```bash
cd frontend
npm install
```

## 启动开发服务器

```bash
npm run dev
```

默认地址：http://127.0.0.1:5173

开发环境所有请求统一以 `/api` 开头，由 Vite 代理转发到后端并移除 `/api`
前缀（后端默认 http://127.0.0.1:8000，后端地址通过环境变量可改，见下）。
代理属于同源请求，**不触发浏览器 CORS 预检**，因此本机开发无需任何额外配置。

后端**现已装配 CORS**（`app/core/cors.py`，允许来源由后端环境变量
`CORS_ALLOW_ORIGINS` 控制，默认放行 `http://127.0.0.1:5173` 与
`http://localhost:5173`）：如果前端改为**直连后端**（`VITE_API_BASE_URL`
指向后端地址）或前后端分离部署，需要把前端站点来源加进后端的
`CORS_ALLOW_ORIGINS`（英文逗号分隔，支持 `*`）。鉴权走 `Authorization`
请求头而非 Cookie，所以前端**不需要**开启 `withCredentials`。

### 后端启动（联调前提）

在仓库根目录（`main.py` 所在目录）执行：

```bash
# 需提供环境变量（至少含 32 字符的 AUTH_SECRET_KEY；DEEPSEEK/DASHSCOPE 的 key
# 在本阶段仅影响导入，可先给占位值，但聊天/知识库模块需要真实值）
export AUTH_SECRET_KEY='至少32个随机字符'
export DEEPSEEK_API_KEY='your-key'     # 仅启动需要占位，聊天阶段用真实值
export DASHSCOPE_API_KEY='your-key'    # 同上
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

若想使用独立数据库而不污染仓库根目录的 `chat_history.db`，可额外设置
`CHAT_DB_PATH` 与 `LANGGRAPH_CHECKPOINT_DB_PATH` 指向临时文件。

## 环境变量

复制 `.env.example` 为 `.env.local`（**禁止提交**）后按需修改：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `VITE_API_BASE_URL` | `/api` | Axios 请求基础地址；开发用 `/api`（代理转发），部署时改为真实网关地址 |
| `VITE_PROXY_TARGET` | `http://127.0.0.1:8000` | Vite 开发代理目标后端 |
| `VITE_CHAT_TIMEOUT_MS` | `180000` | 聊天请求独立长超时（毫秒）；聊天不自动重试，超时后界面提示「结果状态可能不确定，请刷新历史后再决定是否重发」 |
| `VITE_KNOWLEDGE_UPLOAD_TIMEOUT_MS` | `180000` | 知识库上传请求独立长超时（毫秒）；上传不自动重试，超时后界面提示「结果状态可能不确定，请先刷新文档列表，再决定是否重新上传」 |

`.env.local` 中不得存放真实密钥；仓库只提交 `.env.example` 占位文件。

前端相关的**后端**环境变量（配置在后端 `.env`，不是前端 `.env.local`）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `CORS_ALLOW_ORIGINS` | 本机 5173 的两个写法 | 允许跨域访问后端的来源（英文逗号分隔，支持 `*`）；仅在直连后端/分离部署时需要配置 |

## 登录态与安全边界（重要事实说明）

- 后端**没有 refresh token，也没有服务端 logout 接口**。因此「退出登录」
  只清理前端本地状态（令牌/用户/企业选择），令牌只能等待自然过期
  （有效期由后端 `ACCESS_TOKEN_TTL_SECONDS` 决定，默认 **1 周（604800 秒）**，
  登录响应 `expires_in` 会返回秒数，前端据此推算过期时间并做预过期校验）；
  前端按此设计，不存在服务端强制下线能力。
- 访问令牌保存在 **localStorage**。这是常见的便捷做法，但其安全性依赖
  站点本身（localStorage 可被同源 XSS 读取），**不是完全安全的存储方案**；
  生产环境应配合 CSP、HttpOnly Cookie 方案或短期令牌与刷新机制演进。
- 任意接口返回 401（登录接口自身的失败除外）都会触发统一的会话过期处理：
  清除本地令牌/用户/企业 → 跳转登录页并提示「登录已过期」。
- 界面上的角色（admin/agent）只用于展示与按钮显隐；**所有权限由后端在每个
  写操作上实时校验**，前端缓存不是安全依据。

## 聊天模块的事实与边界（重要）

- **历史恢复与结构化信息**：服务端历史接口只保存用户问题与 Agent 最终
  回答文本；本页新收到的响应可展示 citations/events/pending_approvals，
  刷新后不会恢复——前端不伪造历史引用或审批卡片。
- **聊天超时语义**：聊天请求使用独立长超时（`VITE_CHAT_TIMEOUT_MS`，
  默认 180 秒）且**不自动重试**；超时或断网后提示「结果状态可能不确定，
  请先刷新历史再决定是否重新发送」，避免重复用户消息或重复提案。
- **系统提示词**：会话级附加偏好，不能覆盖服务器规则；空白输入不能提交。
- **待审批提案**：`pending_approvals` 是唯一可信来源（不解析自然语言）；
  卡片「查看审批」跳转审批详情 `/app/approvals/:approvalId`（审批已被处理时
  详情页展示最新状态；不可访问时回到列表并提示）。

## 审批中心的事实与边界（重要）

### 路由与权限

- 路由：`/app/approvals`（审批列表，默认「待审批」筛选）与
  `/app/approvals/:approvalId`（审批详情）；两页都沿用认证与租户守卫。
- **agent（客服角色）**：可以查看审批列表、详情、版本历史与 Run 状态；
  界面显示明确只读说明（「只有管理员可以作出决定或恢复执行」），不展示
  决定表单与恢复按钮。
- **admin**：额外可以批准 / 修改后批准 / 拒绝，以及恢复符合条件的 Run。
  前端角色只用于界面展示；后端在每个决定/恢复请求上实时校验权限
  （agent 强制请求会得到 403 APPROVAL_ADMIN_REQUIRED），前端即使误显
  按钮也不会绕过后端。

### 审批决定不可逆 + 200/201/202 语义

- 决定一旦提交落库**不可修改或删除**；提交前必须经过确认对话框
  （含决定、金额、币种、修改字段、备注与模拟执行提示），确认前不发起
  任何请求；提交期间按钮 loading、禁止重复点击、不做自动重试。
- 决定接口按真实 HTTP 状态码分流：

| 状态码 | 语义 | 前端行为 |
| --- | --- | --- |
| 201 | 首次决定且自动恢复成功 | 提示「审批已提交，工作流已恢复。」并重载详情/Run/列表 |
| 202 | 决定已保存但工作流恢复失败 | 提示「可以稍后恢复」，**保留恢复入口**，重读服务端状态 |
| 200 | 相同决定的幂等重复提交 | 提示「已加载最新状态」，不重复追加本地版本/决定 |
| 409 | 已被其他操作处理 | 提示并立即刷新详情与列表，不保留可提交旧表单 |
| 422 | 字段校验失败 | 字段错误映射回表单项，**不清空用户已输入内容** |
| 403 | 角色已变化 | 刷新当前企业角色列表并提示 |

### Run 恢复语义

- 恢复按钮只在「当前角色是 admin + 最近一次决定要求恢复（resume_required）
  或 Run/执行错误可重试 + Run 不是明显不可恢复终态」时显示（条件集中在
  `canResumeRun` 派生函数，模板不散落逻辑）。
- 200 = 恢复成功或幂等返回已有结果；409 = 状态已变化/不可恢复（刷新后
  隐藏旧按钮）；**503 = 本次恢复失败，但已经保存的审批决定仍然有效，
  可稍后再试**——界面保留决定/版本/审批事实并允许按钮重新启用；
  403 = 权限变化，刷新角色。恢复请求不做自动重试。
- Run 状态轮询：仅 queued/running 时每 5 秒刷一次；等待审批或终态停止；
  页面隐藏/卸载/切换企业即停止；不做重叠请求。

### 数据与模拟免责声明

- 审批列表/详情**不写入 localStorage**；切换企业或退出登录时统一清理，
  旧企业在途请求返回后按失效标记丢弃，不污染新企业。
- 列表接口不返回总数：UI 按「最近一页是否拉满 limit」判断是否还有更多，
  不伪造审批总数；列表项不展示用户名（接口只给 user_id）。
- **退款/补偿均为模拟业务记录**：执行成功会写入模拟业务记录并可标记订单
  状态，但**不代表真实资金到账或真实发券**；界面在决定表单、确认对话框、
  Run 面板三处如实注明。

### 人工验收路径（审批中心）

1. 启动后端与前端（见上文），以 admin 登录并选择企业；
2. 通过聊天产生退款/补偿提案（真实模型 Key 就绪时），或后端脚本造数；
3. 侧栏「审批中心」→ 默认「待审批」Tab 出现该提案（金额/状态/订单/版本）；
4. 进入详情：检查基本信息、请求版本、版本时间线（V1 为初始版本）、
   Run 面板（完整状态与可空字段「—」）；
5. 以 admin 提交批准：确认对话框 → 201 提示 → 详情转为已批准、Run 成功；
6. 换 agent 账号登录：详情只读说明与无表单/无恢复按钮；
7. 直接访问 `/app/approvals/not-exist`：回到列表并提示「审批不存在或已
   不可访问」；
8. 聊天中点击「查看审批」卡片：跳到对应审批详情；
9. 窄屏宽度检查：列表/详情无横向溢出、表单可用。

## 知识库模块的事实与边界（重要）

### 路由与权限

- 路由：`/app/knowledge`（文档列表）与 `/app/knowledge/:documentId`
  （文档详情）；两页都沿用认证与租户守卫，直接访问详情 URL 可加载，
  404 时回到列表并提示「文档不存在或已不可访问」。
- **agent（客服角色）**：可以查看文档列表、详情、版本历史与最近入库
  任务；界面显示明确只读说明（「只有管理员可以上传文档、上传新版本、
  停用或启用文档」），不展示上传、停用、启用与上传版本操作。
- **admin**：额外可以上传新文档、上传新版本、停用/启用（均需确认）。
  前端角色只用于界面展示；后端在每个写操作上实时校验权限
  （agent 强制请求会得到 403），前端即使误显按钮也不会绕过后端。

### 支持的文件与限制（前后端一致）

- 仅支持 `.md` / `.markdown` / `.txt`（扩展名不区分大小写；`.md`/
  `.markdown` 映射为 Markdown，`.txt` 映射为纯文本）；**Word（.docx）
  当前不能通过 HTTP 上传**，虽然领域枚举里有 `word`（界面按「只读兼容」
  展示，且不提供上传新版本入口）。
- 单文件 ≤ **2 MiB**（`2 × 1024 × 1024` 字节），必须**非空**且为
  **合法 UTF-8**（前端用 TextDecoder 严格模式校验，仅改善体验，服务端
  仍会兜底校验并返回 422）。
- 文档标题 strip 后 1–200 字符；**版本上传不提供重命名能力**：标题固定
  为当前文档标题（后端仍要求 title 字段，前端自动传递）。
- 新版本文件类型必须与原文档 `source_type` 一致（markdown 文档接受
  `.md`/`.markdown`，text 文档只接受 `.txt`）。

### 同步长耗时上传与不自动重试

- 知识入库会同步执行：文档解析 → 分块 → Embedding → 向量库写入 →
  激活版本，**请求可能持续较长时间**（独立长超时
  `VITE_KNOWLEDGE_UPLOAD_TIMEOUT_MS`，默认 180 秒）；
- 上传期间：表单锁定、防重复点击、显示「正在上传并建立知识索引，
  请勿重复提交。」（**没有百分比进度**）、阻止误关闭（无取消按钮，
  且不提供声称能终止服务端处理的入口）；
- **上传绝不自动重试**：服务端可能在请求返回前就完成了入库与版本激活，
  客户端重试会造成重复文档或重复版本；超时/断网后提示「结果状态可能
  不确定，请先刷新文档列表，再决定是否重新上传。」，失败时**保留标题
  与文件选择**；
- 上传回执（`IngestionReceiptResponse`）按 `status` 分流：
  - `succeeded`：展示成功、刷新列表（新文档跳转详情、新版本刷新详情）；
  - **`deduplicated=true`**：内容与当前有效版本完全相同，服务端复用既有
    版本，**未创建重复版本**——界面明确提示「上传内容与当前有效版本
    相同，未创建重复版本。」，不得虚构新版本条目；
  - `queued` / `running`：显示「后台入库中」并保存 `job_id` 启动轮询；
  - `failed`：展示安全失败状态并查询任务详情，不把文档描述为可检索。

### 入库任务状态与轮询

- 任务状态：`queued`（排队中）/ `running`（处理中）/ `succeeded`（成功）/
  `failed`（失败）；查询接口 `GET /knowledge/ingestion-jobs/{job_id}/`
  返回 `attempt_count`、`error_code`、`error_message`、`started_at`、
  `finished_at` 等（前端只展示服务端安全 error_code/message，不展示
  堆栈/密钥/正文）。
- 任务轮询：仅 `queued`/`running` 时每 **5 秒**查询一次；页面隐藏即暂停、
  恢复可见后继续、页面卸载或切换企业即停止；不允许请求重叠；
  `succeeded`/`failed` 后停止；每次任务状态更新后同步刷新文档详情。
- **限制（如实记录）**：当前后端没有任务列表接口，刷新页面后如果没有
  保存 job_id，只能通过文档详情里的 `latest_job` 恢复有效版本最近一次
  任务——前端**不伪造任务历史**，也**不把 job_id 写入 localStorage**。

### 停用与启用语义

- **停用**（仅 active 文档）：确认文案「停用后，该文档将不再参与客服
  Agent 的知识检索，但版本记录不会删除。」；停用后文档不再参与检索，
  版本与任务记录保留。
- **启用**（仅 disabled 文档）：确认文案「启用后，当前有效版本将重新
  参与知识检索。」；成功后刷新列表与详情。
- `processing` / `failed` 状态**不提供**直接启用/停用入口（后端对这些
  状态没有更深层的合法性校验）；**不提供删除功能**（后端没有删除接口）。

### 其它事实

- 文档详情与版本响应**不含文档正文、下载地址或原始文件**：界面明确
  说明「文档正文、预览与下载暂不提供」，**不伪造**正文预览/下载/分页/
  检索统计。
- 文档列表接口**无分页、无搜索**：搜索（标题/文档 ID）、状态筛选、
  来源类型筛选与排序全部为**前端本地处理**（默认「最近更新」，排序选项
  含最近更新/最早创建/最近创建/标题），界面明确标注「本地处理」，不会
  向后端发送不存在的查询参数。
- 空值统一显示「—」；未知枚举值安全降级为原始字符串；状态文字与颜色
  同时展示（颜色不单独表意）。
- 知识库数据**不写入 localStorage**；切换企业或退出登录时由 tenantReset
  统一清理，旧企业在途响应按失效标记丢弃，不污染新企业。

### 人工验收路径（知识库）

1. 启动后端与前端（真实 Embedding/Qdrant 就绪时），以 admin 登录并
   选择企业；
2. 侧栏「知识库」→ 列表页：空态 → 点击「上传文档」→ 选择 `.md` 文件
   并填写标题 → 上传成功提示 → 自动进入文档详情；
3. 详情页检查：基本信息、版本历史（v1 当前有效版本标记）、入库任务
   面板（成功后 succeeded；无任务时明确空状态）；
4. 上传新版本：确认对话框 → 成功后详情刷新为新版本激活（版本号递增）；
5. 重复上传同一内容：提示「上传内容与当前有效版本相同，未创建重复版本。」
   （版本列表不增加）；
6. 停用文档：确认 → 列表与详情状态变为已停用 → 上传新版本仍可用；
7. 启用文档：确认 → 状态恢复已启用；
8. 上传一个 `processing`/`failed` 状态文档（如提供非法内容触发失败）：
   详情展示失败说明与任务错误码，无启用按钮；
9. 换 agent 账号登录：列表/详情只读说明、无上传/停用/启用/上传版本按钮；
10. 直接访问 `/app/knowledge/not-exist`：回到列表并提示「文档不存在或
    已不可访问」；
11. 搜索/筛选/排序：输入标题或文档 ID、筛选状态/类型、切换排序，
    确认均为本地处理（请求面板无新请求）；
12. 窄屏宽度检查：筛选区、卡片、详情与版本历史无横向溢出；
13. 上传请求超时/断网（可临时缩短
    `VITE_KNOWLEDGE_UPLOAD_TIMEOUT_MS`）：提示结果状态可能不确定、
    表单保留，刷新列表后确认是否已入库。

## 成员管理模块的事实与边界（重要）

### 路由与权限

- 路由：`/app/members`（成员管理），沿用认证与租户守卫；侧栏「成员管理」
  入口已从占位改为真实导航。
- **成员列表企业内所有角色可读**（`GET /organizations/{id}/members/`）：
  agent 能看到同事目录，界面显示只读说明。
- **写操作仅 admin**：添加成员、修改角色、移除成员。前端按
  `GET /organizations/` 返回的角色隐藏入口，但**后端在每个写操作上实时重读
  Membership 校验**（agent 得到 403，非成员得到 404）；写操作被 403 拒绝时
  store 会主动刷新企业列表，让界面入口与服务端状态收敛。

### 自我管理限制（关键规则）

- 后端**禁止 admin 修改或移除自己的成员关系**（409），目的是保证企业始终
  至少保留一名管理员（唯一管理员无法自我降级或退出企业）。
- 界面因此对「我」那一行不提供改角色/移除入口，并显示
  「不能管理自己的成员关系」；页头提示当前管理员数量与该规则。
- **企业退出/转让接口后端仍未提供**（见 `docs/frontend/api-inventory.md`
  5.4 第 3 条），界面不伪造此类入口。

### 数据与交互事实

- 成员列表接口**无分页、无搜索参数、不返回总数**：搜索用户名与角色筛选
  全部为**前端本地处理**，界面标注「本地筛选：显示 X / Y 位」。
- **添加成员**按对方**已注册的精确用户名**查找：前端做与注册同规则的前置
  校验（3–32 位小写字母/数字/下划线），404 提示「用户不存在，请确认对方已
  注册且用户名正确」，409 提示「该用户已是本企业成员」。
- **改角色与移除都必须二次确认**（确认前不发送任何请求）；移除确认文案
  说明「该成员立即失去本企业数据访问权限；其已产生的会话与审批记录会保留，
  重新加入需再次添加」。
- 后端**没有成员数汇总接口**：页面直接使用列表长度；不伪造统计数字。
- 成员数据**不写入 localStorage**；切换企业或退出登录时由 tenantReset
  统一清理，旧企业在途响应按失效标记丢弃。

### 人工验收路径（成员管理）

1. 以 admin 登录并选择企业 → 侧栏「成员管理」→ 列表展示成员用户名、
   角色与加入时间，自己的行有「我」标记；
2. 点击「添加成员」→ 输入未注册用户名 → 本地校验拦截（不足 3 位）；
   输入不存在的用户名 → 提示用户不存在；
3. 输入已注册用户名并选择角色 → 添加成功 → 新成员出现在列表；
4. 对某成员切换角色下拉 → 弹出确认框 → 取消则不发请求；确认后角色更新，
   列表徽标同步变化；
5. 对自己那一行确认**没有**改角色/移除入口，并显示规则说明；
6. 点击某成员「移除」→ 确认框 → 确认后该成员从列表消失；
7. 换 agent 账号登录：能看到成员列表与只读说明，无添加成员按钮、
   无角色下拉与移除按钮；
8. 搜索框输入用户名、角色筛选切换：均为本地过滤（无新请求）；
9. 移除某成员后，用该成员账号刷新页面：企业列表不再包含该企业，
   自动回到企业选择页。
