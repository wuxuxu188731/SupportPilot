main.py 组装路由
app.include_router()
app.include_router(
  creat_conversation_router(
    chat_service=chat_service,
    get_current_user=get_current_user
  )
)
app.include_router(
  create_auth_router(
    auth_service=auth_service,
    get_current_user=get_current_user
  )
)

其中router.py 里面的create_conversation_router方法中：
对外暴露的接口有：创建会话create_conversation、向模型聊天chat、修改会话的系统提示词update_conversation_system_prompt
1.创建会话：
先接收请求参数，校验请求参数(如果参数不合法就抛出HTTPException);
调用chat_service里面的create_conversation()方法，将合适的参数传入(在调用service层的方法时要考虑方法里面是否会抛出异常，
如果会抛出异常，需要捕获异常并转成HTTPException返回)；
返回接口结果response

2.向模型聊天：
先接收请求参数，校验请求参数(如果参数不合法就抛出HTTPException)；
调用chat_service里面的chat方法，将合适的参数传入(调用service方法时要考虑方法里面是否会抛出异常，这里调用时用try,except包裹
捕获可能出现的会话不存在异常ConversationNotFoundError并且转成HTTPExeption抛出)；
返回接口调用结果response

3.修改会话的系统提示词：
先接收请求参数，校验请求参数(如果参数不合法就抛出HTTPException)；
调用chat_service里面的update_system_prompt方法(调用service方法时要考虑方法里面是否会抛出异常，这里调用时用try,except
包裹，捕获可能出现的会话不存在异常ConversationNotFoundError并且转成HTTPExeption抛出)；
返回接口调用结果response

其中auth_router.py里面的create_auth_router方法中：
对外暴露的接口有：注册接口、登录接口、ME接口(用于判断用户的token是否过期)
1.注册接口：
先接收请求参数，校验请求参数(如果参数不合法就抛出HTTPException)；
调用auth_service里面的register注册方法(调用对应方法时要考虑异常...)
返回接口调用结果response

2.登录接口：
....类似步骤

3.Me接口:
请求参数只有一个token，直接调用对应的方法然后进行返回，这个被调用的方法可以直接是create_auth_router函数里面的Callable参数
这样对比硬编码(从对应的包中导入这个函数)的好处有三点：
好处1：可以避免循环导入，如果auth_router.py 直接 from app.api.dependencies import get_current_user，
而 dependencies.py 又引用了 auth_router的东西，就会出现循环导入，python直接报错Import error。这么做可以避免报错
好处2：测试非常方便，不需要mock,不需要patch，保证测试之间零耦合。如果在auth_router.py里面直接 from ... import ...
那么在写路由测试的时候就必须使用@patch来做，非常麻烦
好处3：这样写依赖关系清晰，不同函数之间的调用链明确

路由层面总结：main.py里面只负责组装路由，导入对应的依赖并注入。
routerxxx.py中使用路由工厂，在create_xxx_router()方法里面增加接口方法，最后返回APIRouter
接口方法中，一般都是三步走：1.接收请求的参数，校验参数是否合法(如果在路由层面没有校验那么可能在调用对应的service方法里面进行了
校验，如果service层没有对参数进行校验，那么肯定在存储层对参数进行了校验，如果参数不合法就会顺着调用链一层一层向上抛出异常，此时
在路由层捕获对应的异常然后抛出HTTPException即可)    2.调用service层里面已经写好的方法(要使用try，同时捕获对应方法可能抛出
的异常并抛出对应的HTTPException)  3.返回接口调用的结果
------------------------------------------------------

service层：
chat_service:
定义Service类，在类中写__init__方法(init方法一般用于为Service类进行依赖初始化：持久化对象store,Callable对象)，
然后添加对应的具体方法(被router接口所调用的方法)，在方法中一般通过调用store对象中的方法来操作数据库，通过调用Callable对象进行
业务流程
service层一般不需要校验参数，校验参数的工作一般在路由层或者持久层，但是会抛出异常

stroe层：
持久层，一般都是一些CRUD，在操作数据库之前一定要校验参数是否合法，是否符合业务逻辑，不符合预期抛出异常

pydantic对象一般都用在路由层，路由层的接口接收的JSON对象会被转成对应的pydantic对象，接口的response_model也是pydantic对象
实体对象一般都使用@dataclass，实体对象一般映射数据库里面的表
